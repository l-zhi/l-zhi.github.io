## 01. 欢迎新同事「@Claude」

前几天，Claude 上线了一个新功能，叫「Claude Tag」。

名字取得很有迷惑性,听着像个不起眼的小功能。

但它不是。

![图片](/img/wechat/3df1fc9620b7680bab06d2a9.png)

这个功能让 Claude 正式混进人类的团队里了——以一个「新同事」的身份，甚至有了自己的独立账号,你可以像 @同事 那样,直接 @它干活。

第一时间就试了下，我让它写一个自我介绍，然后一分钟就写完了。

![图片](/img/wechat/c96fdb97534bf88d2bd286f5.png)

整个体验就像对待一个同事一样，它不仅能写文档，还能改bug，开发需求，体验下来非常惊艳。

再回头看这大半年 Claude 团队推出的一连串"团队协作"功能,就会发现，Claude Tag 不是突然冒出来的，而是水到渠成。

2025年末 MCP协议

2025年11月 Claude Plan Mode (规划模式)，嵌入技术方案，产品文档设计

2026年4月 Claude Design 画设计稿，嵌入开发上游

2026年5月 推荐HTML与团队协作，云端部署Claude

2026年6月 Claude Tag 数字员工接入Slack

程序员们终于开发了一套技术，把自己淘汰掉了。

而这个剧本，我感觉似曾相识。

一千八百年前，有个人，就是这么干的——司马懿。

## 02. 司马懿,是怎么把曹魏熬垮的

公元 200 年，曹操强征司马懿出仕。

司马懿装病，一装就是七年。曹操不耐烦了，扔下一句:"再装,就杀。"

![图片](/img/wechat/c89ee89702c705c897b01855.jpg)

司马懿这才出山。

出山之后,他每一步,都踩在曹魏的命脉上——替曹操管屯田,替曹丕守后方,替曹叡顶北线。

诸葛亮六出祁山,挡在前面的,是他。

可他一辈子没打过几场漂亮仗。他打的全是消耗战、防御战、补给战——尽是些没人爱干、又非干不可的脏活。

曹操看他:"狼顾之相,不可付兵权。"

曹丕、曹叡两代,把他当一把"最锋利、最听话的工具人"。

所有人都觉得,他翻不了天。

司马懿一句不辩。

他熬死了曹操（220 年）。

他熬死了曹丕（226 年）。

他熬死了曹叡（239 年）。

249 年,高平陵之变。七十岁的司马懿,一夜之间,把曹魏最后的辅政大臣曹爽连根拔起。

他的孙子司马炎登基,建立西晋。

![图片](/img/wechat/dec5ffc4a0ef50491f8d8e75.jpg)

整个曹魏, 被一个所有人都看不上眼的"工具人",活活熬走了。

## 03. AI Coding,是怎么一步步接管开发的

司马懿的路,我这十年,是亲眼看着 AI 重走了一遍。

2014年，我第一次见识"代码补全",是在一次内部讨论会上。

那时候所谓的补全,就是把写得好的代码片段存成模板,用快捷键调出来。

![图片](/img/wechat/69ebb33d53aa66b146662606.png)

比如新建一个移动端 HTML 页面,只要打出 \`H5\`,按一下 Tab,就能生成下面这一整段:

说白了,就是个"花式复制粘贴",方便大家新建文件时复用。

2016年，有同事推荐了一个 VSCode 插件,能"智能补全"。

原理大概是扫描你代码库里相似的片段,你一边打字,它一边联想。比如我打出Chat,它就把相关的代码全给我联想出来:

![图片](/img/wechat/cd49a92937605382c9d91824.png)

但这本质上不是"智能",是"快速搜索"。

2024年，AI Coding来了，Cursor已经能写一些输入输出简单的代码。基础的方法块丢给它基本能实现——但要让我为它掏钱,还不至于。

![图片](/img/wechat/66d1ac5458142d1f5ecd77d4.jpg)

2025年初,各家大厂的 Coding 工具集体涌现。那会儿我在阿里,用得多的是 AoneCode CLI 配 Qwen大模型，已经能扛起 60% 的开发了。

但阿里全是微服务,架构盘根错节,改一个功能,往往牵动 2、3 个团队、4、5 个项目。所以方案还得我来设计,AI 只负责在各个项目里按固定套路写方法,最后我再来联调。

![图片](/img/wechat/7e3cff70239a1b94ed926c87.jpg)

那时候,AI 干的还是杂活:写写测试用例,做做数据库的增删改查。

2025年, Claude Code 横空出世。一切开始变得不一样。

![图片](/img/wechat/eb8806da23d4724c7fc6e53d.jpg)

它一开始厉害的主要是对代码库的理解，而且写出来的代码比其他的Coding工具可靠、成功率高。

然后它不安分了。它开始讲 Spec,开始问你要更多上下文,开始自己写需求文档,开始一点点改变整个开发协作的方式。

再然后,身边的人慢慢都不自己写代码了,全交给 Claude Code。

一开始还会假模假式地做做 Code Review,后来连这步也省了——让 Claude Code 自己 review 吧。

![图片](/img/wechat/623c0c48a46b77f8acc9932c.jpg)

就这么一步步放权下去,方案设计、bug 修复,它全包了。

直到某一天,大家猛地反应过来:已经很久没碰过代码了,自己项目里的代码,反而读不懂了。

可 Claude 的脚步,还没停。

![图片](/img/wechat/b8d53584e4e94b49a0b9060b.png)

它发现自己写的 spec 是纯文本,很多人看不懂、读不进去,于是开始"迁就"人类——把文档输出成更好读的 HTML。

以前它每跑一次脚本都得人来审批,后来,需要审批的次数越来越少。

它开始自己部署独立的服务,要独立的账号。

然后,赢得团队里越来越多人的信任。

直到, Claude Tag 发布。

网上有个回复,我觉得特别贴切,他只配了一张图：

现在：🤖 👨🏻 👨🏻 👨🏻 👨🏻

未来：🤖 🤖 🤖 🤖 👨🏻

从模板,到补全,到能写 30%,到能写 60%,再到今天——你回过神才发现,它早就不是来"帮你"的,它是来"接班"的。

Claude 一声不吭,已经悄悄长成了程序员的事实标准。

这就是司马懿那套剧本——

> **别人在搞演讲,我在管档案。**  
> **别人在做 Demo,我在写测试。**  
> **等所有的开发都跑在我身上的那天,你想换我,都换不掉了。**

## 04. 回头看程序员自己

讲完 Claude,再回头看我们自己。

程序员看 AI Coding 的眼神，和当年曹操看司马懿,一模一样:

"它就是个补全工具。

" "它就是个写测试的。"

"它就是个改 bug 的。"

"它就是个写 boilerplate 的。"

"真正的架构、决策、创意,还得我来。"

可是兄弟,你算过没有——这些加起来，就是你工作的 80%。

## 05. 写在最后

司马懿没有杀曹操。

他只是在曹操的眼皮底下，把所有人都看不上的活,一件一件,默默干了五十年。

AI Coding 也不会完全"推翻"程序员。

它会在你身边，一年一年,把你嫌烦的事,一件一件,接走。

直到某一天,你打开自己的代码库,发现里头每一个文件、每一次提交、每一个测试,它都比你熟。

那一天,你才会想起开头那个 Claude Tag。

它看起来,只是又一个不起眼的小功能。

可你把这大半年的更新连起来看——终端、客户端、 Spec、Desgin、Workflow、HTML，再到 Tag——你会发现,它早就不是一个"工具"了。

它是一个，已经搬进你工位、正在一点点接走你所有活的同事。

![图片](/img/wechat/306373c636c5a8bc47833aea.png)

而且这个同事，不睡觉,不抱怨,不跳槽,只会一年比一年,更懂你的代码库。

司马懿,用了五十年。

它,可能只需要三年。

![图片](/img/wechat/a5c9ce3af088259ba0fe1881.jpg)

多年以后，面对强大的AI，我也许会回想起，我曾经坐在公司办公桌前，双手摸着略带油滑的键盘，眼睛直盯着昏黄的显示器，一字一句敲代码的那个遥远的下午。
